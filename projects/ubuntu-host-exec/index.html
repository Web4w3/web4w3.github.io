# Ubuntu Host Exec

An MCP server that runs shell commands on a home Ubuntu machine and returns the output to any MCP client. One deliberately small tool — exec — runs each command with bash as a regular user (no sudo), published over HTTPS through a Cloudflare Tunnel and guarded by a bearer token. An AI assistant can operate the machine it serves — check services, read logs, move files — from anywhere, without opening SSH to the internet.

❯cat ubuntu-host-exec/ARCHITECTURE.md

## How It Works

The server listens on the host itself; a Cloudflare Tunnel publishes it over HTTPS, and every request must carry the bearer token. A tool call arrives with a command string and an optional timeout; the server runs it via bash as the host's regular user, captures stdout, stderr and the exit code, appends the call to a local audit log, and returns the result. The blast radius of a bad command is one unprivileged account on one home machine.

## Features

  • +Single exec tool — full bash, and nothing else to learn or leak
  • +Runs as an unprivileged user; no sudo path exists
  • +Reachable only through a Cloudflare Tunnel — no open ports, no public SSH
  • +Bearer-token authentication on every call
  • +Per-call timeout, so runaway commands stay on a leash
  • +Every command audit-logged on the host

## Installation

1

Run the server on the host

A small Node.js MCP server exposing one exec tool over HTTP, bound to the host itself. Commands run as your regular user — there is no sudo path.

2

Publish it through a tunnel

A Cloudflare Tunnel routes a hostname to the local port and terminates HTTPS. No inbound ports are opened on the host or the router.

3

Point your MCP client at it

Remote HTTP server with bearer-token auth.

{
  "mcpServers": {
    "host-exec": {
      "url": "https://exec.example.com/mcp",
      "headers": {
        "Authorization": "Bearer <your-token>"
      }
    }
  }
}
